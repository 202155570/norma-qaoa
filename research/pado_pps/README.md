# PADO PPS 연구 — ETF 선택 QAOA

ETF 선택 문제(MaiQ 위성 ETF 목적함수)를 QAOA로 다룰 때, NORMA의 PADO Pauli-propagation surrogate(`padopauli`)를 쓸 수 있는 조건을 찾고, 그 위에서 각도를 학습하는 연구다. 2026-10-22 ~ 2026-11-03에 Windows CPU 머신에서 수행했고, GPU 서버에서 이어서 진행하기 위해 정리했다.

수치마다 출처를 표시했다.
- **[측정]** 이 디렉터리의 파일로 재현되는 값
- **[기록]** 이전 세션에서 측정했으나 그때의 스크립트가 OS 임시폴더 정리로 사라져, 세션 기록에만 남은 값

## 1. 결론 요약

1. **원래 식(조밀한 상관, k개 고정 Dicke 시작)에서는 PPS를 쓸 수 없다. [기록]**
   - 50개 중 6개: PPS 오차가 QAOA 이득의 125%(p=1), 149%(p=2), 컴파일 11~40분.
   - 원인은 두 가지다.
     - Dicke 준비 회로(CX 2,496개): padopauli는 |0…0⟩에서만 시작한다.
     - 조밀한 결합: 1,225쌍 중 989쌍이 0이 아니다.
2. **각도는 작은 문제에서 학습해 큰 문제로 옮길 수 있다(파라미터 전이). [기록]**
   - 24개짜리 부분문제에서 학습한 각도가 50개 문제에서 ⟨E⟩ 이득의 98.7~99.9%를 낸다(50개 중 3개, p=1~6).
   - 50개 중 6개, p=2에서는 99.3%다.
   - 다만 최적해 확률 P(opt)는 72% 수준으로 덜 따라온다.
3. **PADO 친화 변형식에서는 PPS가 매우 정확하다. [측정]** (`verdict.md`)
   - 변형식: 시장 공통분을 1차 항으로 옮기고, 잔차 결합을 ETF당 3개로 희소화하고, λΣx 항을 쓰고, |+⟩에서 시작한다.
   - N=50/100/150, p=1·2에서 PPS 오차가 이득의 1e-4 이하이고, 컴파일은 ≤317초다.
   - 하지만 N=150에서는 변형식 최적해가 원래 식 상위 3.5%에 그친다. 희소화로 상관 0.70 초과 패널티 쌍이 잘렸기 때문이다. 판정은 **보류**.
4. **원래 식으로 6개를 보정하면 QAOA 정보는 결과에 기여하지 않는다. [측정]** (`exp_a.md`)
   - 1,000샷에서는 QAOA, 점수순, 무작위가 모두 같은 최적에 도달한다.
   - 샷이 적을 때 QAOA는 점수순 배치보다 일관되게 못하다.
5. **10년 워크포워드 백테스트에서 어떤 선택 식도 동일가중·SPY를 이기지 못했다. [측정]** (`bt.md`)
   - 샤프: MaiQ 0.33, PADO 변형식 0.12, 클러스터 0.17, 점수 상위 6 0.44, 동일가중 0.48, SPY 0.67.
   - 쌍별 차이의 95% CI는 모두 0을 포함한다.
6. **PPS로 학습한 각도가 정확 학습과 같은 성능을 내는 조건을 찾는 중이다. [측정, 진행 중]** (§5)
   - N=20, 차수 3, 인스턴스 1개: w=5면 p=5까지 정확 학습의 추가 이득을 99.9% 이상 재현한다.
   - w=4는 p=4에서 0.889로 기준 0.90 아래다.

## 2. 이전 세션 결과 [기록]

### MaiQ 12개 중 3개 (합성 상관, seed 0~2)

각도는 ⟨E⟩ 최소화로 정했다(정답을 모르는 기준).

| 방식 | p=2 결과 | 99%로 최적해를 보는 shots |
|---|---|---|
| 페널티 A(Σx−k)² + X 믹서 | 순수 탐색 배율 0.2~1.1 (p=1~4) | 약 1,640 |
| XY 링 믹서 + Dicke 시작 | P(opt) 4.1~4.3% | 약 105~111 |
| XY 완전 믹서 | P(opt) 29~34% | — |

- 균등 추출일 때 P(opt)는 1/220 = 0.45%다.
- XY 링의 P(opt)는 p=4에서 6.2~6.9%, p=12에서 6.8~15.1%다.
- 세션 기록에서 지표 단위가 섞여 있어, 표는 기록된 단위 그대로 옮겼다.

heavy-hex 하드웨어용으로 트랜스파일하면 CZ 게이트 수는 다음과 같다. 그래서 하드웨어에서는 p=2~3이 현실적이다.

| p | 페널티 방식 | XY 방식 |
|---|---|---|
| 2 | 530 | 756 |
| 4 | 1,066 | 1,142 |
| 12 | 3,025 | 2,702 |

12큐비트에서는 정확 시뮬레이션이 ms 단위라 PPS가 필요 없다.

### 실데이터 50개 ETF (기준일 2026-10-22)

**50개 중 3개 (19,600개 상태)**
- 최적해: XLV, EWT, USO.
- P(opt): p=1 0.014%, p=5 0.093%(4,950 shots).
- Dicke 준비 회로만 PPS로 돌린 오차: w=4 1.6, w=5 0.22. p=1 이득 0.61보다 커서 사용 불가.

**50개 중 6개 (15,890,700개 상태)**
- 최적해: XLP, EWZ, EWT, USO, XBI, KRE (E* −105.99).
- 정확 시뮬레이션:

| p | 이득 | P(opt) | 99% shots |
|---|---|---|---|
| 1 | 2.24 | 4.9e-7 | 941만 |
| 2 | 2.92 | 7.3e-7 | 634만 |

- PPS(w=4): 오차가 이득의 125%(p=1), 149%(p=2)로 사용 불가.

### 파라미터 전이 (50개 중 6개, n=24 학습)

| p | ⟨E⟩ 이득 재현율 | 직접 최적화한 P(opt) 대비 |
|---|---|---|
| 1 | 99.3% | 96% |
| 2 | 99.3% | 72% |

p=3·4 전이 각도의 ⟨E⟩ 이득은 직접 최적화한 p=2의 112~121%지만, P(opt)는 오히려 그보다 낮았다.

## 3. PADO 친화 변형식 연구 [측정]

판정 보고서는 `verdict.md`, 연구 범위 문서는 저장소의 `docs/2026-11-03-pado-friendly-contract.md`·`-plan.md`에 있다.

**데이터**
- Yahoo 공개 차트 API, 150개 ETF(기존 50 + 자산군별 100), 2024-10-29~2026-11-02 공통 504일.
- 가격 테이블 내용 해시: `ce3658dd…cbde`.

**변형식** (`build.py`, `ppsl.make_problem`)
1. Q_ij ≈ c + a_i + a_j를 최소제곱으로 근사하고 1차 항으로 옮긴다. |S|=6에서는 원래 식과 정확히 같다.
2. 잔차 |R| 상위 쌍을 차수 ≤3으로 남긴다. 상관 0.70 초과 쌍을 우선한다.
3. λ는 p=1에서 기대 선택 수가 6이 되도록 정한다.

**검증**
- 빛원뿔 정확 시뮬레이터(`lc.py`)와 20큐비트 전체 상태벡터: 최대 차이 3.6e-14.
- PPS 회로 규약: 12큐비트, w=12에서 4.4e-15.

| N | p=2 PPS 오차/이득 (w=4 / 5 / 6) | 변형식 최적해의 원래 식 순위 |
|---|---|---|
| 50 | 4.7e-4 / 3.1e-5 / 4.0e-7 | 상위 0.009% (전수 탐색) |
| 100 | 4.5e-5 / 2.8e-6 / 1.7e-8 | 상위 0% (100만 표본) |
| 150 | 1.0e-4 / 4.3e-6 / 2.3e-8 | **상위 3.5%** (100만 표본) |

**주의할 점**
- 이득의 대부분은 λ 항이다. 그래서 결합항 대비 오차도 함께 봤고, 최대 5.7e-4다.
- p=1은 빛원뿔이 6큐비트 이하라서 판별력이 없다.

## 5. 진행 중: PPS로 각도 학습 (`ppsl.py`, `small.py`, `large.py`)

**목표**: PPS로 학습한 QAOA 각도가 정확 학습과 같은 성능을 내는 조건(깊이 p, 결합 차수 d, 절단 가중치 w)의 지도를 만든다.

**성공 기준** (운영자, 2026-11-03)
- capture = (E1 − E_exact(PPS 각도)) / (E1 − E_exact(정확 학습 각도)) ≥ 0.90.
- E1은 정확 학습 p=1 에너지다.
- 정확 학습 체인이 국소 최적에 걸릴 수 있으므로, 분석 때는 두 체인 중 더 좋은 쪽을 정확 기준으로 삼는다.

**검증 방법**
- N=20: 전체 상태벡터로 정확 대조.
- N=50~150: 빛원뿔 정확값과 대조할 수 있는 곳(최대 빛원뿔 ≤ 20큐비트)에서는 대조한다. 나머지는 w를 하나 올렸을 때 값이 수렴하는지로 확인한다.

빛원뿔 최대 크기(큐비트 수):

| 차수 d | p=1 | p=2 (N=50 / 150) | p=3 (N=50 / 150) |
|---|---|---|---|
| 3 | 6 | 14 / 14 | 24 / 28 |
| 4 | 8 | 19 / 24 | 32 / 51 |
| 5 | 10 | 26 / 37 | 46 / 75 |

**지금까지 결과** (`small.jsonl`; N=20, d=3, 인스턴스 0)

| p | w=4 capture | w=5 capture | w=5 컴파일 / 학습 |
|---|---|---|---|
| 2 | 1.000 | 1.000 | 1 s / 3 s |
| 3 | 1.053* | 1.000 | 6 s / 13 s |
| 4 | **0.889** | 1.000 | 24 s / 53 s |
| 5 | 0.921 | 0.999 | 50 s / 120 s |

\* 정확 학습 체인이 국소 최적에 걸려 1을 넘었다.

**중단 경위**: 이 탐색은 w=6 측정 중 개발 머신(RAM 15.7 GB)의 메모리 부족으로 중단됐다. w=5가 이미 정확값에 붙어 있어서, 이후 계획에서는 w=6을 뺀다.

## 6. GPU 서버에서 이어 하기

### 설치

```bash
git clone -b pado-pps-study <repo-url> && cd <repo>/research/pado_pps
python3.12 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt              # torch는 서버 CUDA에 맞는 빌드로
pip install /path/to/padopauli-2.0.2-*.whl   # 사내 배포 wheel
```

### 데이터

가격 테이블은 저장소에 없다. 개발 머신의 `out/pado_pps_data.zip`(약 2.8 MB)을 서버로 복사해 이 디렉터리에 푼다.

```bash
unzip pado_pps_data.zip -d . && sha256sum -c SHA256SUMS
```

기대 해시:
- `prices.json` a15c8d90…693a
- `prices10.json` 2ecb7414…e8ab

다시 받을 수도 있지만(`python -I fetch.py tickers.json raw 3y`, `python -I parse.py tickers.json raw prices.json`; 10년치는 `fetch.py … raw10 10y` + `parse10.py`), 기준일이 바뀌어 수치가 달라진다.

### 실행 환경 변수

| 변수 | 기본값 | GPU 서버 값 | 역할 |
|---|---|---|---|
| `PADO_PRESET` | `cpu` | `gpu` 또는 `hybrid` | padopauli 컴파일 프리셋 |
| `PF_DEVICE` | `cpu` | `cuda` | 정확 상태벡터(torch) 장치 |

GPU 설정은 개발 머신에 GPU가 없어 **검증하지 못했다**. 먼저 자체 점검부터 돌린다.

```bash
python small.py selftest      # 상태벡터 = 빛원뿔 = PPS(w=n), 기울기 점검
python bt.py selftest         # 국소탐색 = N=50 전수 탐색 최적
python pf_check.py U3         # 변형식 연구 산출물 점검
PADO_PRESET=gpu PF_DEVICE=cuda python small.py selftest
```

### 다음 실행

```bash
# 1) 소규모 지도: d=3,4,5 × 인스턴스 0~2 × w=4,5 × p=1..5 (이어 하기 가능)
python -u small.py run 3,4,5 0,1,2 5 4,5 small.jsonl

# 2) 큰 N: (N, d) 하나씩. p=1..5, w=4로 학습하고 w=5로 수렴 점검
for n in 50 100 150; do for d in 3 4 5; do python -u large.py $n $d 5 4 large.jsonl; done; done
```

**참고 수치 (개발 머신 CPU)**
- 소규모: 인스턴스 하나의 정확 학습 체인(p=1~5)이 약 7분이고, 이 시간이 대부분이다. 결과는 `cache/`에 저장된다.
- 큰 N: N=150, d=3, p=2, w=6 PPS가 컴파일 317초에 최대 메모리 6.8 GB였다. p와 w가 커지면 메모리가 빠르게 는다.

**규칙**: 한 설정이 컴파일 40분 또는 메모리 8 GB를 넘으면 "불가"로 기록한다. 서버 사양에 맞춰 이 한도를 조정해도 된다.

### 결과 정리

- `small.jsonl`의 capture를 (d, w, p)별 중앙값으로 묶는다.
- `large.jsonl`의 `w_gap_over_extra_gain` ≤ 0.10이면 w 수렴으로 본다. p≤2에서는 `E_exact_of_pps_angles`와 대조한다.
